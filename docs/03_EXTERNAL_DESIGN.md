# ピクトリ（Pictri）外部設計書

バージョン: 1.0  
作成日: 2026-06-07  
対象フェーズ: MVP（開発MVP〜公開MVP）

---

## 1. 外部設計の目的

本書は、ピクトリのユーザーから見える仕様を定義することを目的とする。

外部設計が定義する範囲は以下である。

- 各画面の構成・表示内容・ユーザーが実行できる操作
- 画面間の遷移ルールと状態の引き渡し
- エラー・空状態・権限未許可時の表示
- デザイン方針と UI 上の禁止事項

内部実装の詳細（クラス設計・データフロー・アーキテクチャ）は別途、内部設計書（`docs/04_INTERNAL_DESIGN.md`）に記載する。

本書は `docs/02_REQUIREMENTS.md` の機能要件を受けて作成されており、両者は整合していること。

## 2. アプリ全体の画面構成

ピクトリの画面は以下の3層で構成される。

```
Layer 1: ルート画面（タブバー）
  ├── Home
  ├── Map
  ├── Camera（タブ起動は Map から spotId を受け取った後が原則）
  └── Memories

Layer 2: モーダル・シート（タブの上に重なる）
  ├── QuestSpotDetailView（Map からボトムシートとして表示）
  ├── FriendProfileSheet（Home の投稿ヘッダーからシートとして表示）
  ├── JQAccountSheetView（Home 右上アイコンからシートとして表示）
  └── ExplorePhotoDetailSheet（Memories Explore カードからシートとして表示）

Layer 3: インライン展開（同一画面内で展開）
  ├── コメント入力フィールド（Home 投稿カード内）
  └── PrefectureMemoryDetailView（Memories Collect サマリーカードから遷移）
```

### 画面一覧

| 画面ID | 画面名 | 種別 | MVP実装 |
|-------|-------|-----|---------|
| SCR-HOME | Home | タブ画面 | 開発MVP |
| SCR-MAP | Map | タブ画面 | 開発MVP |
| SCR-CAMERA | Camera | タブ画面（Map から起動） | 開発MVP |
| SCR-MEMORIES | Memories | タブ画面 | 開発MVP |
| SCR-SPOT-DETAIL | スポット詳細 | ボトムシート | 開発MVP |
| SCR-FRIEND-PROFILE | フレンドプロフィール | シート | 開発MVP |
| SCR-ACCOUNT | アカウント・フレンド管理 | シート | 開発MVP（ローカル） |
| SCR-EXPLORE-DETAIL | Explore 写真詳細 | シート | 開発MVP |
| SCR-PREFECTURE-DETAIL | 県別 Memories 詳細 | Push 遷移 | 開発MVP |

## 3. グローバルナビゲーション設計

### 3-1. ボトムタブバー

ピクトリのメインナビゲーションはボトムタブバーである。

| タブ | アイコン | 役割 |
|-----|-------|-----|
| Home | house | フレンドの旅行投稿フィード |
| Map | map | スポット発見・撮影起点 |
| Camera | camera | 現地撮影（Map から spotId を受け取って起動） |
| Memories | photo.on.rectangle | 自分の旅行記録 |

**タブバーの設計方針:**

- タブバーは常に表示する（全画面モーダル表示中を除く）
- カメラタブはタップで直接 Camera 画面を開くが、spotId なしで開いた場合は「Mapでスポットを選んでください」旨の案内を表示する
- Account / Friend はタブに含めない。Home 画面の右上アイコンからシートとして開く

### 3-2. Account へのアクセス

Account シートは Home 画面の右上アイコンからのみ開く。

- 他のタブに Account アイコンは配置しない
- Account シートはフルスクリーンではなくシート（ドラッグで閉じられる）として表示する

### 3-3. 遷移の原則

| 遷移パターン | 使用場面 |
|-----------|--------|
| タブ切り替え | Home / Map / Camera / Memories の切り替え |
| ボトムシート表示 | Map のスポット詳細 |
| シート表示（モーダル） | Account / フレンドプロフィール / Explore 写真詳細 |
| Push 遷移（NavigationStack） | Memories の県詳細ビュー |
| インライン展開 | Home のコメント入力 |

## 4. Home 画面の外部仕様

### 4-1. 画面の目的

友達や自分の最近の旅行投稿を見て、旅行欲を刺激する画面。SNS としての楽しさを持ちつつ、ピクトリ固有の「旅行写真記録」としての文脈を維持する。

### 4-2. 画面構成

Home 画面は上から以下のセクションで構成される。

```
[ ヘッダー: "ピクトリ" + Account アイコン（右上） ]

[ Hero カード: 自分のスポット訪問進捗 ]
  - 訪問済みスポット数 / 全スポット数
  - 「Mapで探す」導線ボタン

[ 気になるスポットセクション ]
  - 未訪問スポットの横スクロールカード
  - スポット名・エリア名・サムネイル

[ フレンドの旅の記録セクション ]
  - 投稿カード（時系列、7日以内のもの）
  - 空状態: 「フレンドが旅先で記録を残すと、ここに表示されます。」
```

### 4-3. 投稿カードの構成

投稿カードは1件ごとに以下の要素で構成される（詳細は「セクション9 投稿カード仕様」参照）。

```
[ postHeader ]
  - 投稿者アバター + 投稿者名（タップで FriendProfileSheet）
  - スポット名 / エリア名（displayPlace）

[ 写真エリア ]
  - 撮影した写真（全幅表示）

[ postFooter ]
  - いいねボタン + いいね数
  - コメントボタン（タップでコメント入力フィールドをインライン展開）

[ コメント一覧 ]
  - 最大3件を投稿カード下部にインライン表示
  - 3件超は「他Nコメント」等の表示は MVP では省略
```

### 4-4. ユーザーが実行できる操作

| 操作 | 動作 |
|-----|-----|
| いいねボタンをタップ | いいねをトグル（即時反映）。いいね数が増減する |
| コメントボタンをタップ | 投稿カード直下にコメント入力フィールドを展開 |
| 投稿者アバター / 名前をタップ | FriendProfileSheet を表示 |
| Hero カードの「Mapで探す」をタップ | Map タブへ遷移 |
| 気になるスポットカードをタップ | Map タブへ遷移し、該当スポット詳細を開く（将来対応） |
| Account アイコンをタップ | JQAccountSheetView をシートとして表示 |

### 4-5. 表示ルール

- 投稿は `createdAt` から7日が経過すると Home フィードから自動的に非表示になる
- 日数カウントダウン（「あとN日」「まもなく消えます」等）は表示しない
- フィードは時系列（新しい順）で表示する
- 自分の投稿とフレンドの投稿を混在させて表示する
- 投稿詳細専用画面は設けない（カード上でいいね・コメントを完結させる）

## 5. Map 画面の外部仕様

### 5-1. 画面の目的

旅行スポットを地図上で発見し、撮影の動機づけを得る画面。コアフローの起点であり、アプリの中心体験を担う。

### 5-2. 画面構成

```
[ 全画面地図（MapKit） ]
  - スポットピンを表示
  - 訪問済み / 未訪問でピン外観を区別

[ ピン選択時: QuestSpotDetailView（ボトムシート） ]
  - スポット名・エリア名
  - 撮影ステータスチップ（未撮影 / 撮影可能 / 撮影済み）
  - 撮影済み写真のプレビュー（あれば）
  - 「カメラを起動」アクションボタン
```

### 5-3. 地図の表示仕様

| 項目 | 仕様 |
|-----|-----|
| 初期表示エリア | 神奈川県（MVP段階） |
| 対応エリア | 神奈川・東京・京都（MVP段階。順次拡大） |
| ピン表示 | スポットごとに1ピン |
| 訪問済みピン | 撮影済みスポットを視覚的に区別（薄色または撮影済みバッジ） |
| ズーム操作 | ピンチイン / ピンチアウトで自由にズーム可能 |
| エリア選択UI | ボタン選択は設けない。地図を動かして発見する体験を優先する |

### 5-4. スポット詳細（QuestSpotDetailView）の仕様

スポットピンをタップするとボトムシートとして QuestSpotDetailView を表示する。

**表示項目:**

| 項目 | 表示内容 |
|-----|---------|
| スポット名 | `spot.name` |
| エリア名 | `spot.area`（例: 鎌倉・湘南） |
| 撮影ステータスチップ | 「未撮影」/ 「撮影可能」/ 「撮影済み」の3-state |
| 写真プレビュー | 撮影済みの場合は保存済み写真のサムネイル。未撮影の場合は非表示 |
| アクションボタン | 「カメラを起動」（未撮影 / 撮影可能の場合に有効） |

**デザイン制約:**

- 背景は黒基調。白背景は使用しない（Map → SpotDetail → Camera の世界観を維持する）
- ステータスチップの配色: 撮影済みは強調色、撮影可能は通常色、未撮影はグレー

### 5-5. ユーザーが実行できる操作

| 操作 | 動作 |
|-----|-----|
| スポットピンをタップ | QuestSpotDetailView（ボトムシート）を表示 |
| 地図をスクロール・ズーム | 地図を自由に移動 |
| スポット詳細の「カメラを起動」をタップ | Camera 画面を `spotId` とともに起動 |
| ボトムシート外をタップ / 下スワイプ | スポット詳細を閉じる |

## 6. Camera 画面の外部仕様

### 6-1. 画面の目的

現地認証のもと、旅行写真を撮影・保存する画面。Map との世界観を統一し、「場所で撮る」体験を演出する。

### 6-2. 画面の状態遷移

Camera 画面は以下の5状態を持つ。

```
[起動] → [位置確認中] → [撮影可能] or [撮影不可]
                              ↓
                          [撮影中]
                              ↓
                          [保存完了]
```

| 状態 | 表示内容 |
|-----|---------|
| 起動直後 | Map SpotDetail から受け取った `spotId` をもとに位置確認を開始 |
| 位置確認中 | インジケーターを表示（「現在地を確認しています...」） |
| 撮影可能 | カメラプレビューを全画面表示。シャッターボタンが有効になる |
| 撮影不可 | 「このスポットの近くで撮影してください」旨のメッセージ。シャッターボタンは無効 |
| 保存完了 | 「メモリーに保存しました」メッセージ + 「メモリーで確認する」CTA ボタン |

### 6-3. 撮影フロー

MVP のカメラフローは2枚連続撮影（内カメ → 外カメ）である。

```
1. 外カメラ起動 → 撮影（景色・場所）
2. 内カメラ切り替え → 撮影（自撮り）
3. 「メモリーに保存」ボタンをタップ
4. 保存完了 → CTA 表示
```

ユーザーはカメラ切り替えボタンで外カメラ / 内カメラを任意に切り替えられる。撮影順序の強制はしない（フローのガイダンスは表示する）。

### 6-4. UI 要素の仕様

| UI要素 | 仕様 |
|-------|-----|
| シャッターボタン | 中央下部に配置。撮影不可時はグレーアウト |
| カメラ切り替えボタン | シャッターボタン右横に配置 |
| 保存ボタン | ラベル: 「メモリーに保存」。アイコン: bookmark.fill |
| 保存後 CTA | ラベル: 「メモリーで確認する」。Primary スタイルで目立つ配置 |
| スポット名表示 | 画面上部または撮影プレビュー上にスポット名を表示 |

### 6-5. 位置認証の仕様

| 項目 | 仕様 |
|-----|-----|
| 認証方式 | 現在地座標がスポットの `allowedRadius` 内にあるか判定 |
| 判定タイミング | Camera 画面起動時に1回判定する |
| 開発中の解除 | `developerUnlockMode = true`（`#if DEBUG` でのみ切り替え可能） |
| App Store 提出時 | `developerUnlockMode = false`（現地認証が有効） |

### 6-6. 保存時に記録する情報

| フィールド | 内容 |
|-----------|-----|
| `spotId` | Map から受け取ったスポット識別子 |
| `prefectureId` | スポットが属する都道府県 |
| `photoAsset` | 撮影した写真データ（端末フォトライブラリへ保存） |
| `capturedAt` | 撮影日時（ISO 8601） |
| `location` | 撮影時の緯度・経度 |

## 7. Memories 画面の外部仕様

### 7-1. 画面の目的

過去の旅行記録を場所ごとに見返す画面。写真アルバムではなく、「旅行した場所の記録」として整理する。

### 7-2. 2つの表示モード

Memories 画面はヘッダー部のモード切替で「Collect」と「Explore」を切り替えられる。

| モード | 概念 | 表示形式 |
|-------|-----|---------|
| Collect | どの場所を訪れたか | 県別・スポット別の固定グリッド |
| Explore | いつ何を撮ったか | 時系列カルーセル（写真が主役） |

### 7-3. Collect モードの仕様

**トップレベル（県サマリー一覧）:**

```
[ ヘッダー: "メモリー" + モード切替 ]
[ 県チップ（横スクロール）: 「すべて」「神奈川」「東京」... ]

[ 県ごとのサマリーカード ]
  - 県名
  - 写真タイル5枚（撮影済み写真のサムネイル）
  - 進捗バー（訪問済み / 全スポット数）
  - 達成テキスト（「あとNスポット」または「コンプリート」）
```

サマリーカードをタップすると県詳細ビュー（`PrefectureMemoryDetailView`）へ Push 遷移する。

**県詳細ビュー（PrefectureMemoryDetailView）:**

```
[ 3列固定グリッド ]
  - 撮影済みセル: 写真サムネイルを表示
  - 未訪問セル: mappin アイコン（プレースホルダー）
  - グリッドの順序は spotId の gridIndex で固定
```

**Collect モードの設計制約:**

- グリッドの枠数はスポット定義に基づいて固定する（撮影済みが増えるほど枠が埋まる）
- 未訪問セルのプレースホルダーを削除してはならない（「埋めていく体験」の核心）
- ゲームのスコアボードに見えないようにする。達成感は静かに表現する

### 7-4. Explore モードの仕様

**カルーセル表示:**

```
[ 横スクロールカルーセル（スナップスクロール） ]
  - ExplorePhotoCard（写真 + 日付 + スポット名）
  - スワイプで前後の写真に移動
  - タップで ExplorePhotoDetailSheet を表示
```

**ExplorePhotoCard の表示項目:**

| 項目 | 表示形式 |
|-----|---------|
| 写真 | カード全面 |
| 日付 | M月d日（例: 6月7日） |
| スポット名 | カード下部に表示 |
| エリア名 | スポット名の下に小さく表示 |

**ExplorePhotoDetailSheet（写真詳細シート）:**

```
[ 写真全画面 ]
  - 上部 40% は完全透明（写真を主役にする）
  - 下部にグラデーションオーバーレイ
[ キャプション（fade-in） ]
  - スポット名
  - エリア名
  - 日付
[ 右上: close ボタン ]
[ 下部: 「コレクトで見る」テキスト導線 ]
  - タップで Collect モードに切り替え + シートを閉じる
```

写真がない場合の fallback: `mappin.and.ellipse` アイコン（グラデーション背景）を表示する。

## 8. Account / Friend 関連画面の外部仕様

### 8-1. アクセス方法

Account 関連機能はタブバーには含めない。Home 画面の右上アイコンからのみアクセスできる。

```
Home 右上アイコン → JQAccountSheetView（シート）
```

### 8-2. JQAccountSheetView の仕様

Account シートは以下のセクションで構成される。

```
[ 自分のプロフィール ]
  - アバター画像
  - 表示名

[ フレンド一覧 ]
  - フレンドのアバター + 名前
  - （開発MVP ではローカルのモックデータ）

[ フレンド追加 ]
  - ユーザー検索（公開MVP で実装。開発MVP では UI のみ）

[ 設定 ]
  - サインアウト（公開MVP で実装）
  - アカウント削除（公開MVP で実装）
```

### 8-3. FriendProfileSheet の仕様

Home の投稿カードの投稿者名 / アバターをタップすると FriendProfileSheet を表示する。

```
[ 投稿者アバター + 表示名 ]
[ bio / 最近の記録（post.displayPlace） ]
[ 訪問スポット数・記録数（公開MVP での実装） ]
[ フレンド追加ボタン（公開MVP での実装） ]
```

**開発MVP の制約:**

- 開発MVP では `QuestFriendStore`（ローカル）のモックデータで表示する
- フレンド検索・申請・承認は公開MVP（バックエンド接続後）に実装する

## 9. 投稿カードの表示仕様

Home フィードの投稿カードを構成する全要素を定義する。

### 9-1. カード構造

```
┌─────────────────────────────────┐
│ postHeader                      │
│  [アバター]  [投稿者名]           │
│             [displayPlace]      │
├─────────────────────────────────┤
│ 写真エリア（全幅）                │
│                                 │
│                                 │
├─────────────────────────────────┤
│ postFooter                      │
│  [♡ いいね数]  [💬 コメント]     │
├─────────────────────────────────┤
│ コメント一覧（最大3件、インライン） │
│  username: コメントテキスト       │
│  ...                            │
└─────────────────────────────────┘
```

### 9-2. 各要素の詳細

| 要素 | 表示内容 | タップ動作 |
|-----|---------|---------|
| アバター | 投稿者のアイコン画像 | FriendProfileSheet を表示 |
| 投稿者名 | 投稿者の表示名 | FriendProfileSheet を表示 |
| displayPlace | スポット名またはエリア名 | なし |
| 写真 | 撮影した写真（全幅） | なし（MVP段階では写真単体タップは無効） |
| いいねボタン | 「♡」アイコン + いいね数 | いいねをトグル |
| コメントボタン | 「💬」アイコン | コメント入力フィールドを展開 |
| コメント一覧 | ユーザー名 + テキスト（最大3件） | なし |

### 9-3. 表示ルール

- `createdAt` から7日が経過した投稿はフィードに表示しない
- 日数カウントダウンは表示しない
- 投稿詳細専用画面へは遷移しない（カード上で完結）
- いいね数は `baseLikeCount + isLiked ? 1 : 0` でインライン計算する

## 10. いいね・コメントの操作仕様

### 10-1. いいね

| 項目 | 仕様 |
|-----|-----|
| 操作 | postFooter のいいねボタンをタップ |
| 動作 | いいね状態をトグル（ON ↔ OFF）。即時反映 |
| 表示変化 | ボタンアイコンが filled / unfilled に切り替わる。いいね数が ±1 される |
| 状態管理 | `likedPostIds`（ローカル Set）で管理（開発MVP） |
| 他ユーザーへの反映 | 開発MVP ではローカルのみ。公開MVP でバックエンド接続後に同期 |

### 10-2. コメント

| 項目 | 仕様 |
|-----|-----|
| 操作 | postFooter のコメントボタンをタップ |
| 動作 | 投稿カード直下にコメント入力フィールドを展開。キーボードが表示される |
| 送信 | テキスト入力後にリターンキーまたは送信ボタンで送信 |
| 表示 | 送信後、投稿カード下部のコメント一覧に即時追加される |
| 表示件数 | 最大3件をカード内に表示する。3件超は MVP では省略 |
| 状態管理 | `comments`（ローカル配列）で管理（開発MVP） |
| 他ユーザーへの反映 | 開発MVP ではローカルのみ。公開MVP でバックエンド接続後に同期 |

## 11. Map → Camera → Save → Memories → Home の画面遷移

ピクトリのコアフローにおける画面遷移を定義する。

### 11-1. フロー図

```
[Map タブ]
  ↓ スポットピンをタップ
[QuestSpotDetailView（ボトムシート）]
  ↓ 「カメラを起動」ボタンをタップ
  ↓ activeCameraSpotId に spotId をセット
[Camera タブ（spotId 受け取り済み）]
  ↓ 位置確認 → 撮影可能 → 撮影 → 保存
[保存完了状態]
  ↓ 「メモリーで確認する」をタップ
[Memories タブ（Collect モード）]
  ↓ 該当スポットセルに写真が反映済み
  
  ※ 保存と同時に Home フィードにも投稿が追加される（Home タブへの反映）
```

### 11-2. 各遷移ステップの詳細

| ステップ | 起点 | 終点 | 渡す情報 | 確認状態 |
|---------|-----|-----|---------|---------|
| 1. スポット選択 | Map ピンタップ | QuestSpotDetailView | `spot`（スポット全情報） | 実機確認済み |
| 2. Camera 起動 | SpotDetail の起動ボタン | Camera タブ | `activeCameraSpotId`（spotId） | 実機確認済み |
| 3. 位置確認 | Camera 起動時 | 撮影可能 / 撮影不可 | なし | 実機確認済み |
| 4. 撮影・保存 | シャッター → 保存ボタン | 保存完了状態 | `QuestMemory`（ローカル保存） | 実機確認済み |
| 5. Memories 反映 | 保存完了 | Memories Collect / Explore | なし（Store 経由で自動反映） | 実機確認済み |
| 6. Home フィード反映 | 保存完了 | Home フィード | `QuestPost`（ローカル生成） | 実機確認未完了 |

### 11-3. 遷移時の状態引き渡し

| 値 | 引き渡し方法 |
|----|-----------|
| `spotId` | `ContentView` の `@State activeCameraSpotId` を介して Camera タブに渡す |
| `QuestMemory` | `QuestMemoryStore.save()` を呼び出し、`@Published memories` が更新される |
| `QuestPost` | 保存時に `QuestMemoryStore` が `QuestPost` を生成し、`@Published posts` が更新される |

## 12. エラー・空状態・権限未許可時の表示仕様

### 12-1. カメラ権限未許可

| 状態 | 表示内容 |
|-----|---------|
| カメラ権限が「拒否」 | 「カメラへのアクセスが許可されていません」メッセージ + 「設定を開く」ボタン |
| 「設定を開く」タップ | iOS 設定アプリのピクトリ権限ページへ遷移 |
| シャッターボタン | 権限なしの場合は無効化（グレーアウト） |

### 12-2. 位置情報権限未許可

| 状態 | 表示内容 |
|-----|---------|
| 位置情報権限が「拒否」 | Camera 画面内で「位置情報の許可が必要です」メッセージ + 「設定を開く」ボタン |
| 位置確認中に権限なし | 撮影不可として扱い、適切なメッセージを表示 |

### 12-3. 位置認証失敗（スポットから遠すぎる）

| 状態 | 表示内容 |
|-----|---------|
| 現在地がスポットの許容範囲外 | 「このスポットの近くで撮影してください」メッセージ |
| シャッターボタン | 無効化（グレーアウト） |
| 再試行 | ユーザーが移動した後に再び位置確認が走る（または手動リトライボタン） |

### 12-4. Home フィードが空の場合

| 状態 | 表示内容 |
|-----|---------|
| フレンドの投稿が0件 | 「フレンドが旅先で記録を残すと、ここに表示されます。」 |
| 追加の案内 | Map への誘導ボタン（「スポットを探す」等） |

### 12-5. Memories に記録がない場合

| 状態 | 表示内容 |
|-----|---------|
| 撮影記録が0件 | Collect モード: グリッドはすべてプレースホルダー（mappin アイコン）で表示 |
| Explore モード | カルーセルに表示する写真がない場合は「まだ記録がありません」旨を表示 |

### 12-6. ネットワークエラー（開発MVP では非対象）

開発 MVP はローカル完結のためネットワークエラーは対象外。公開 MVP（バックエンド接続後）に定義する。

## 14. UI 上の禁止事項・デザイン方針

### 14-1. デザイン方針

| 方針 | 詳細 |
|-----|-----|
| 黒白基調 | 背景は黒（またはダークグレー）。白背景は使用しない |
| 高級感・静けさ | 余白を十分に取る。情報を詰め込みすぎない |
| 旅行写真が主役 | 写真をなるべく大きく表示する。UI 要素は写真の邪魔をしない |
| 一貫した世界観 | Map → SpotDetail → Camera → Memories を通じてトーンを統一する |

### 14-2. UI 上の禁止事項

以下は意図的に排除する設計要素である。

| 禁止事項 | 理由 |
|---------|-----|
| BeReal スタイルの強制撮影通知・「あなたの番です」UI | ピクトリは旅行先で任意に撮影するアプリ。日常強制感を出さない |
| Instagram スタイルの探索タブ・リール・おすすめ | フォロー関係のないコンテンツは表示しない |
| 「あとN日」等の投稿消滅カウントダウン | 消滅SNS感・プレッシャー感を排除する |
| スコア・ランキング・ポイント表示 | ゲームアプリに見えないようにする |
| 観光スタンプラリーUI（「スタンプ獲得！」等） | ピクトリは達成記録アプリではなく旅行写真記録アプリ |
| 白背景の画面（Map / Camera 周辺） | 世界観の断絶を防ぐ |
| 投稿詳細専用画面への過度な依存 | いいね・コメントはカード上で完結させる |
| フォロー / フォロワー（非対称）構造 | フレンド（相互）のみ。SNS 的なフォロワー数競争を生まない |
| UI 上の「JapanQuest」表示 | 内部名のため、ユーザーに見える場所には表示しない。「ピクトリ」を使う |

### 14-3. 表示名ルール

| 場面 | 使用する名前 |
|-----|-----------|
| アプリヘッダー・起動画面 | ピクトリ |
| `Text()` 等 UI テキスト | ピクトリ |
| Xcode プロジェクト名・Bundle ID・型名・ファイル名 | JapanQuest（変更は将来タスク） |
