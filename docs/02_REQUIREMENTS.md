# ピクトリ（Pictri）要件定義書

バージョン: 1.0  
作成日: 2026-06-07  
対象フェーズ: MVP（最小限プロダクト）

---

## 1. プロダクトの目的

ピクトリは、旅行先で実際にその場所へ行き、写真を撮り、その体験を友達と共有し、場所ごとの思い出として長期保存できる iOS アプリである。

目的は以下の3点に集約される。

1. **場所起点の記録体験を提供する**  
   「どこに行ったか」「何を撮ったか」が自然に紐づく形で、旅行写真を残せる体験を作る。

2. **旅行の体験価値を長く維持する**  
   投稿は7日間だけ Home に表示され消えるが、Memories には場所ごとに永続保存される。短期的なSNS体験と長期的な旅行記録の両立を実現する。

3. **場所認証によるリアリティを担保する**  
   ユーザーは実際にそのスポットへ行かなければ撮影できない。これにより、写真に「行った証拠」としての意味を与える。

## 2. 対象ユーザー

### プライマリターゲット

| 属性 | 詳細 |
|-----|-----|
| 年齢層 | 大学生・20代前半 |
| 行動様式 | 友達やカップルで国内旅行・日帰り旅行をよくする |
| デバイス | iPhone |
| 技術リテラシー | 一般的なSNSアプリを日常的に使っている |

### セカンダリターゲット

* 旅行写真を場所ごとに整理したい人
* 友達の旅行をカジュアルに眺めたい人
* 将来的な訪日外国人（MVP後の対象）

### MVP段階では対象外にするユーザー

* 訪日外国人（多言語対応が必要なため）
* 全国を頻繁に旅行するヘビーユーザー（スポットカバレッジが限定的なため）
* 高齢者・子供（UXの最適化が別途必要なため）

## 3. MVP 範囲

MVP では以下の価値を最小限の機能で実現する。

> **コアバリュー:** Map でスポットを見つけ、現地で撮影し、Memories に場所ごとの思い出として残す

### MVPフェーズの定義

本書では MVP を以下の2段階に分けて定義する。

| フェーズ | 概要 | バックエンド要否 |
|---------|-----|--------------|
| **開発MVP** | コアフローを端末単体で動作確認する段階。TestFlight 内部テスト相当 | 不要。ローカル / モックデータで代替 |
| **公開MVP** | TestFlight 外部テスト〜App Store 公開の段階。実ユーザーが使う | 必要。Firebase 等のバックエンド接続が前提 |

いいね・コメント・フレンド投稿フィードは、**開発MVP ではアプリ内のローカル状態（モックデータ）で代替する**。実際のユーザー間でこれらが機能するためには、公開MVP でのバックエンド接続が必要になる。

### Must Have（MVP必須）

| 機能 | 理由 |
|-----|-----|
| Mapでスポットを選ぶ | コアフローの起点 |
| Camera で位置認証付き撮影 | 場所起点の差別化の核心 |
| 写真を spotId / prefectureId と紐づけて保存 | Memories 反映の前提 |
| Memories に県別・スポット別で表示 | 長期価値の実現 |
| Home フィードに7日限定投稿として表示 | SNS体験の実現 |
| いいね・コメント（簡易） | 最低限の社交機能。開発MVP ではローカル状態のみ |
| フレンド表示 | Home フィードが成立する前提。開発MVP ではモックデータで代替 |

### Should Have（あれば望ましい）

| 機能 | 備考 |
|-----|-----|
| 友達追加・フォロー | MVP では最小限の実装で可 |
| 訪問済みスポットのピン薄表示 | Map の体験価値向上 |
| 撮影ラベル（日付・場所名） | 写真の付加価値向上 |
| プロフィール画面 | フレンドの記録を見る動線 |

### Later（MVP後）

* グループ旅行機能
* プッシュ通知
* 全国全スポット対応（MVP初期は神奈川・東京・京都を優先）
* 多言語対応（英語・中国語等）
* AI によるスポット推薦
* 観光情報・グルメ情報の統合
* 収益化（広告・プレミアムプラン）
* ランキング・ゲーミフィケーション

## 4. 機能要件

### 4-1. 認証・アカウント

> **開発MVP では不要。** 端末ローカルの固定ユーザーデータで動作確認する。公開MVP（TestFlight 外部テスト以降）で実装が必要になる。

| ID | 要件 | 優先度 |
|----|-----|------|
| F-AUTH-01 | ユーザーはアプリをインストール後、アカウントを作成または既存アカウントでサインインできる | 公開MVP |
| F-AUTH-02 | プロフィールには表示名・アイコン画像を設定できる | Must |
| F-AUTH-03 | サインアウトができる | Must |
| F-AUTH-04 | アカウント削除ができる | Should |

### 4-2. フレンド

> **開発MVP では `QuestFriendStore`（ローカル）のモックデータで代替する。** フレンド検索・申請・承認は公開MVP でバックエンド接続後に実現する。

| ID | 要件 | 優先度 |
|----|-----|------|
| F-FRIEND-01 | ユーザーIDまたはユーザー名でフレンドを検索できる | 公開MVP |
| F-FRIEND-02 | フレンド申請・承認ができる | 公開MVP |
| F-FRIEND-03 | フレンドの最新投稿を Home フィードで見られる（開発MVP：モックデータで確認） | Must |

### 4-3. Map

| ID | 要件 | 優先度 |
|----|-----|------|
| F-MAP-01 | 日本地図（初期は神奈川・東京・京都）を表示できる | Must |
| F-MAP-02 | スポットをピンとして地図上に表示できる | Must |
| F-MAP-03 | スポットをタップするとスポット詳細画面（QuestSpotDetailView）を表示できる | Must |
| F-MAP-04 | スポット詳細から Camera 画面を起動できる（spotId を渡す） | Must |
| F-MAP-05 | 訪問済みスポットを視覚的に区別して表示できる（薄表示またはバッジ） | Should |
| F-MAP-06 | ズームレベルに応じて都道府県ピン・スポットピンを切り替え表示できる | Should |

### 4-4. Camera

| ID | 要件 | 優先度 |
|----|-----|------|
| F-CAM-01 | Map から渡された spotId を受け取り、撮影画面を起動できる | Must |
| F-CAM-02 | 現在地が対象スポットの許容範囲内にある場合のみ撮影を許可する | Must |
| F-CAM-03 | 外カメラ・内カメラを切り替えて撮影できる | Must |
| F-CAM-04 | 撮影した写真に日付・スポット名ラベルを付与できる | Should |
| F-CAM-05 | 撮影後に写真を保存する（spotId / prefectureId と紐づけて）| Must |
| F-CAM-06 | 保存完了後に Memories への導線（CTA）を表示できる | Must |
| F-CAM-07 | カメラ権限が拒否された場合に適切なエラーと設定誘導を表示できる | Must |

### 4-5. Memories

| ID | 要件 | 優先度 |
|----|-----|------|
| F-MEM-01 | 撮影・保存された写真を県別・スポット別に整理して表示できる | Must |
| F-MEM-02 | 訪問済みスポットを写真サムネイルで表示できる | Must |
| F-MEM-03 | 未訪問スポットをプレースホルダーとして表示できる（グリッド枠を維持する） | Must |
| F-MEM-04 | Collect モード（スポット固定グリッド）と Explore モード（時系列カルーセル）を切り替えられる | Must |
| F-MEM-05 | Explore モードでカードをタップすると写真詳細シートを表示できる | Must |
| F-MEM-06 | 県ごとの訪問進捗（訪問済み / 全スポット数）を表示できる | Should |

### 4-6. Home

> **開発MVP では、いいね・コメントはローカル状態のみ（他ユーザーには反映されない）。** フレンド投稿はモックデータで表示を確認する。実ユーザー間で機能させるには公開MVP でのバックエンドが必要。

| ID | 要件 | 優先度 |
|----|-----|------|
| F-HOME-01 | フレンドと自分の投稿を時系列フィードで表示できる | Must |
| F-HOME-02 | 投稿は撮影後7日間のみ Home フィードに表示し、その後は自動で消える | Must |
| F-HOME-03 | 投稿にいいねができる（即時反映） | Must |
| F-HOME-04 | 投稿にコメントを入力・表示できる（インライン、最大3件表示） | Must |
| F-HOME-05 | 投稿者のプロフィールシートを表示できる | Should |
| F-HOME-06 | フィードが空の場合は Map への誘導文言を表示できる | Must |
| F-HOME-07 | 自分のスポット訪問進捗を Hero カードで表示できる | Should |

## 5. 非機能要件

### 5-1. パフォーマンス

| 項目 | 基準 |
|-----|-----|
| アプリ起動時間 | コールドスタートで3秒以内 |
| 地図描画 | スポットピン表示まで2秒以内 |
| 写真保存 | 保存完了まで3秒以内 |
| フィードスクロール | 60fps を維持すること |

### 5-2. プラットフォーム・対応環境

| 項目 | 基準 |
|-----|-----|
| 対応OS | iOS 17以降 |
| 対応デバイス | iPhone（iPad は MVP対象外） |
| 言語 | 日本語のみ（MVP段階） |
| ダークモード | 対応必須（黒基調UIのため） |

### 5-3. プライバシー・パーミッション

| 項目 | 要件 |
|-----|-----|
| 位置情報 | 撮影時のみ使用（使用中のみ許可。常時追跡は行わない） |
| カメラ | 撮影画面起動時に許可を求める |
| フォトライブラリ | 写真保存時に許可を求める（写真のみ追加を使用） |
| 権限拒否時 | 適切なエラーメッセージと設定アプリへの誘導を表示する |

### 5-4. データ・ストレージ

| 項目 | 要件 |
|-----|-----|
| 写真保存先 | 端末のフォトライブラリ（MVP段階ではクラウド同期は対象外） |
| アプリ内データ | `QuestMemoryStore` を通じて永続化（`UserDefaults` / ローカルJSON） |
| フレンドデータ | ローカル管理（MVP段階。Firebase 接続は後続フェーズ） |

### 5-5. セキュリティ

| 項目 | 要件 |
|-----|-----|
| 位置情報の扱い | 撮影可否判定にのみ使用。第三者送信はしない |
| 写真データ | 端末外に送信しない（MVP段階。クラウド機能導入時に別途設計） |

### 5-6. UI・アクセシビリティ

| 項目 | 要件 |
|-----|-----|
| デザイン方針 | 黒白基調・高級感・余白・静けさを重視 |
| フォントサイズ | Dynamic Type に対応すること（最低限の対応） |
| タッチターゲット | 44pt × 44pt 以上を確保すること |
| アニメーション | `Reduce Motion` 設定を尊重すること |

## 6. MVP では対象外にする機能

以下は明示的にMVP外とする。スコープ外を明確にすることで、開発リソースをコアフローに集中させる。

| カテゴリ | 対象外機能 | 理由 |
|---------|-----------|-----|
| データ同期 | クラウド同期（iCloud / Firebase） | MVP はローカル完結 |
| 通知 | プッシュ通知（いいね・コメント通知） | バックエンド接続が前提 |
| ソーシャル | フォロー/フォロワー（非対称フォロー） | フレンド（相互）のみで十分 |
| コンテンツ | 全国全スポット対応 | 初期は3県程度に限定 |
| 国際化 | 多言語対応（英語・中国語等） | 日本語のみで検証 |
| 地図 | ルート案内・ナビ機能 | スポット発見と撮影が目的 |
| メディア | 動画撮影・GIF | 写真のみ |
| 収益 | 課金・広告 | 検証フェーズでは不要 |
| AI | スポット推薦・写真解析 | インフラ整備後 |
| 旅行情報 | 観光情報・グルメ情報 | コアコンセプトとずれる |
| ゲーム | ランキング・スコア・バッジ収集 | ゲームアプリに見せない |

## 7. 画面別要件

### 7-1. Home 画面

**目的:** 友達や自分の旅行投稿を見て、旅行欲を刺激する。

**表示する情報:**
- フレンドと自分の投稿（7日以内）
- 投稿に紐づくスポット名・写真・投稿者名
- いいね数・コメント（最大3件表示）
- 自分のスポット進捗 Hero カード
- フィードが空の場合: Map への誘導文言

**ユーザーが実行できるアクション:**
- いいね（タップでトグル、即時反映）
- コメント入力・送信（インライン、キーボード表示）
- 投稿者のプロフィールシートを開く
- Map タブへ遷移する（Hero カードまたはタブバー）
- Account シートを開く（右上アイコン）

**制約・ルール:**
- 投稿は7日が経過すると Home フィードから自動的に消える（Memories には残る）
- 日数カウントダウン（「あとN日」等）は表示しない（消滅SNS感を避けるため）
- BeReal のようなリアルタイム強制感を出さない

---

### 7-2. Map 画面

**目的:** ユーザーが旅行スポットを発見し、撮影の動機づけを得る。

**表示する情報:**
- 日本地図（初期は神奈川・東京・京都のスポット）
- スポットピン（訪問済み・未訪問で視覚的に区別）
- スポット詳細（名称・エリア・撮影状況・写真プレビュー）

**ユーザーが実行できるアクション:**
- 地図をスクロール・ズームする
- スポットピンをタップしてスポット詳細を開く
- スポット詳細から Camera 画面を起動する

**制約・ルール:**
- ボタンによるエリア選択は行わない（地図を動かして発見する体験を重視）
- スポット詳細の UI は黒基調で統一する（Map → SpotDetail → Camera の世界観を維持）
- Map から渡す情報: `spotId`（Camera が撮影位置を判定するために必要）

---

### 7-3. Camera 画面

**目的:** 現地認証のもと、旅行写真を撮影・保存する。

**状態:**
1. **起動前:** Map の SpotDetail から `spotId` を受け取る
2. **位置確認中:** 現在地がスポットの許容範囲内かどうか判定する
3. **撮影可能:** カメラプレビューを表示し、シャッターを有効にする
4. **撮影不可:** 位置が遠すぎる旨のメッセージを表示する（developerUnlockMode で開発中は解除可）
5. **保存完了:** 完了メッセージ + Memories への CTA を表示する

**ユーザーが実行できるアクション:**
- 外カメラ・内カメラの切り替え
- シャッターを押して撮影する
- 撮影後に保存する
- 保存完了後に Memories を開く

**制約・ルール:**
- 保存ボタンラベル: 「メモリーに保存」（bookmark アイコン）
- 保存後 CTA ラベル: 「メモリーで確認する」
- カメラ権限が拒否されている場合は撮影不可を明示し、設定アプリへ誘導する
- 写真は `spotId` / `prefectureId` / `capturedAt` / `location` と紐づけて保存する

---

### 7-4. Memories 画面

**目的:** 過去の旅行記録を場所ごとに見返す。

**2つの表示モード:**

| モード | 説明 |
|-------|-----|
| Collect モード | 県別・スポット別の固定グリッド。撮影済みは写真、未訪問はプレースホルダー |
| Explore モード | 時系列の横スクロールカルーセル。写真が主役 |

**Collect モードの要件:**
- 県ごとにサマリーカードを表示する（写真タイル5枚・進捗バー・達成テキスト）
- 県詳細ビューではスポット固定グリッド（3列）を表示する
- 未訪問スポットはプレースホルダー（`mappin` アイコン）として表示する
- コンプリート時に達成感を演出する（視覚的強調）

**Explore モードの要件:**
- スポットに紐づく写真を時系列カルーセルで表示する
- カードに日付（M月d日）・スポット名・エリア名を表示する
- カードタップで全画面の写真詳細シートを表示する
- 詳細シートから「コレクトで見る」導線で Collect モードへ切り替えられる

## 8. コアフロー要件

ピクトリのコアフローは以下の5ステップで構成される。このフローが成立することが MVP の根幹条件である。

```text
Map → Camera → Save → Memories → Home
```

### ステップ詳細

| ステップ | 要件 | 完了条件 |
|---------|-----|---------|
| **1. Map でスポット選択** | 地図上のピンをタップし、スポット詳細を開いて Camera を起動できる | `spotId` が Camera に渡される |
| **2. Camera で撮影** | Camera が `spotId` を受け取り、現地認証の上で撮影できる | シャッターが押せて写真が取得できる |
| **3. Save（保存）** | 写真を `spotId` / `prefectureId` / `capturedAt` と紐づけて永続保存できる | `QuestMemoryStore.save()` が成功する |
| **4. Memories に反映** | 保存後すぐに Memories の該当スポットセルに写真が表示される | Collect / Explore 両モードで写真が見られる |
| **5. Home に投稿として表示** | 保存と同時に Home フィードに投稿として追加される | フレンドと自分のフィードに投稿カードが表示される |

### フロー要件の補足

- ステップ1〜4は現時点で実機確認済み
- ステップ5（Home フィード反映）は実機確認が未完了
- コアフローを壊す変更は、必ず確認してから実施すること
- フロー上の各画面遷移は、状態の引き渡し（`spotId` 等）が確実に行われること

## 9. 高レベルのデータ要件

### 主要データモデル

| モデル | 主要フィールド | 役割 |
|-------|-------------|-----|
| `QuestSpot` | `id`, `name`, `prefecture`, `coordinate`, `allowedRadius` | スポットの定義（Map 表示・Camera 認証の基準） |
| `QuestMemory` | `id`, `spotId`, `prefectureId`, `photoAsset`, `capturedAt`, `location` | 撮影記録（Memories 表示の元データ） |
| `QuestPost` | `id`, `userId`, `spotId`, `photoAsset`, `createdAt`, `likeCount`, `comments` | Home フィード表示用投稿 |
| `QuestUser` | `id`, `displayName`, `avatarImage` | ユーザー情報 |
| `QuestFriend` | `userId`, `friendId` | フレンド関係（相互） |

### データの関係性

```text
QuestSpot ─── (1:N) ─── QuestMemory   （1つのスポットに複数のMemoryが紐づく）
QuestMemory ─── (1:1) ─── QuestPost   （Memoryを保存すると同時にPostが生成される）
QuestUser ─── (1:N) ─── QuestPost    （1人のユーザーが複数のPostを持つ）
QuestUser ─── (N:M) ─── QuestFriend  （相互フレンド関係）
```

### データ保持ルール

| データ | 保持期間 | 保持場所 |
|-------|---------|---------|
| QuestMemory（写真・場所記録） | 永続 | ローカルストレージ |
| QuestPost（Home フィード投稿） | 7日間（表示上の制限） | ローカルストレージ |
| QuestSpot（スポット定義） | 永続 | アプリバンドル（モックデータ） |
| フレンド関係 | 永続 | ローカルストレージ（MVP段階） |

## 10. MVP の受け入れ基準

以下の全条件を満たしたとき、MVP として受け入れる。

### コアフロー
