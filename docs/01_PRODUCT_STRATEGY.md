# Pictri / ピクトリ Product Strategy

## 1. Product Summary

ピクトリは、旅行先で実際にその場所へ行き、写真を撮り、その体験を友達と共有し、あとから場所ごとの思い出として残せるiOSアプリである。

単なる写真SNSではなく、地図・場所・撮影・記憶を中心にした「場所起点の旅行写真SNS」として設計する。

中心体験は以下である。

```text
Mapでスポットを見つける
→ 実際にその場所へ行く
→ Cameraで撮影する
→ Homeで友達に共有される
→ 7日後にHomeから消える
→ Memoriesに場所ごとの思い出として残る
```

## 2. Product Vision

ピクトリの目的は、旅行中の写真を単なる画像として保存するのではなく、「どこに行ったか」「誰と行ったか」「どの場所を訪れたか」が自然に残る体験を作ることである。

Instagramのような投稿中心SNSでも、BeRealのような日常即時投稿アプリでも、Google Photosのような保管アプリでもない。

ピクトリは、旅行体験を場所ごとの記憶として蓄積するアプリである。

## 3. Core Concept

ピクトリのコアコンセプトは以下である。

```text
場所に行った証拠として写真を撮る
撮った写真は一時的に友達へ共有される
時間が経つとSNSフィードからは消える
しかし、場所ごとの思い出としてMemoriesに残る
```

この設計により、短期的にはSNSとしての楽しさを持ち、長期的には自分の旅行記録として価値を持つ。

## 4. Target Users

初期ターゲットは、以下に絞る。

### Primary Target

* 大学生
* 20代
* カップル
* 友達と旅行する層
* 国内旅行や日帰り旅行をよくする層

### Secondary Target

* 写真で思い出を残したい旅行好き
* 旅行先を記録したい人
* 友達の旅行を軽く見たい人
* 将来的な訪日外国人旅行者

初期段階では、訪日外国人や全国の旅行者全体を狙いすぎない。まずは日本国内の若年層旅行者に絞り、神奈川・東京・京都などの限定エリアで体験価値を検証する。

## 5. User Problem

旅行中、ユーザーは多くの写真を撮る。しかし、あとから見返すと以下の問題が起きやすい。

* どこで撮った写真か分かりにくい
* 写真がスマホ内に埋もれる
* 友達との旅行体験が一時的な投稿で終わる
* 行った場所の達成感が残りにくい
* 旅行の記録が場所ごとに整理されない

既存SNSでは「見せる写真」が中心になりやすく、写真フォルダでは「保存」はできても「体験の意味」が残りにくい。

## 6. Solution

ピクトリでは、写真を以下の情報と紐づけて保存する。

* userId
* spotId
* prefectureId
* capturedAt
* location
* photoAsset
* memoryId
* postId

これにより、写真は単なる画像ではなく、「どの場所で撮った思い出か」として扱われる。

ユーザーはHomeで友達の最近の投稿を見て、Mapでスポットを探し、Cameraで撮影し、Memoriesで過去の旅行記録を見返す。

## 7. Differentiation

ピクトリの差別化要素は以下である。

### 1. Place-first Experience

普通のSNSは投稿や人物が中心だが、ピクトリは場所が中心である。

### 2. Location-authenticated Photo

ユーザーは実際にその場所へ行って撮影する。これにより、写真に「行った証拠」としての意味が生まれる。

### 3. Temporary Social Feed

Homeの投稿は7日間だけ表示される。これにより、SNSとしての新鮮さを保ちながら、長期保存はMemoriesに任せる。

### 4. Memories by Prefecture and Spot

写真をただ一覧表示するのではなく、都道府県・スポットごとに整理する。訪れたスポットだけが写真で埋まり、未訪問スポットはプレースホルダーとして残る。

### 5. Travel Memory, not Ranking

ランキングやゲーム性を強くしすぎない。競争よりも、旅行の記憶と友達との共有を重視する。

## 8. Product Positioning

ピクトリの立ち位置は以下である。

```text
Instagram:
映える写真を投稿するSNS

BeReal:
日常の瞬間を撮るSNS

Google Photos / Apple Photos:
写真を保存・整理するアプリ

旅行予約アプリ:
ホテル・航空券・観光情報を探すアプリ

Pictri:
実際に行った旅行先を写真と場所で記録し、友達と共有するアプリ
```

ピクトリは、写真SNS・旅行アプリ・アルバムアプリの中間に位置するが、中心価値は「場所ごとの思い出」である。

## 9. Key Screens

ピクトリの主要画面は以下の4つである。

```text
Home
Map
Camera
Memories
```

### Home

友達や自分の最近の投稿を見る画面。

役割:

* 友達の旅行投稿を見る
* 自分の投稿を見る
* いいねする
* コメントする
* 投稿者プロフィールへ進む
* 7日以内の投稿だけ表示する

HomeではSNS感を残す。ただし、投稿詳細画面に依存しすぎず、フィードカード上で軽く反応できる設計にする。

### Map

旅行スポットを発見し、撮影へ進む画面。

役割:

* 日本地図を表示する
* 都道府県ピンを表示する
* ズームするとスポットピンを表示する
* 訪問済みスポットを薄く表示する
* スポット選択後にCameraへ進む

Mapはアプリの中心体験である。ボタンでエリアを選ばせるのではなく、地図を動かしながらスポットを発見する体験を目指す。

### Camera

実際のスポットで写真を撮影する画面。

役割:

* 選択したspotIdを受け取る
* 位置情報で撮影可能か判定する
* 外カメラ・内カメラで撮影する
* 日付・場所ラベルを付ける
* 撮影後に保存する

Cameraは通常のカメラではなく、旅行先の景色と自分を残すための撮影体験として設計する。

### Memories

過去の旅行記録を場所ごとに見返す画面。

役割:

* 都道府県ごとに思い出を表示する
* スポットごとに固定グリッドで表示する
* 訪問済みスポットを写真で埋める
* 未訪問スポットをプレースホルダーとして残す
* タップしてスポットごとの思い出を見る

Memoriesはピクトリの長期価値である。投稿が消えた後も、旅行の記録は場所ごとの思い出として残る。

初期公開版で入れる機能は以下に絞る。

* ランキング

## 11. Initial Area Strategy

最初から全国全スポット対応はしない。

初期検証エリアは以下を優先する。

```text
神奈川
東京
京都
```

特に神奈川は、江ノ島・鎌倉・横浜・箱根など、若年層旅行者にとって使いやすいスポットが多いため、初期検証に向いている。

最初は各都道府県に大量のスポットを入れず、1県あたり5〜10スポット程度から始める。

## 12. Release Strategy

開発は以下の順番で進める。

```text
1. 設計書の作成
2. コアフローの完成
3. SNS機能の最小実装
4. UI/UXの統一
5. 実機テスト
6. TestFlight配布
7. 外部テスト
8. App Store提出
```

現実的な公開目標は以下である。

```text
TestFlight内部テスト: 2026年8月上旬
TestFlight外部テスト: 2026年8月中旬〜下旬
App Store公開: 2026年9月中旬
```

ただし、機能を増やしすぎた場合は公開時期が遅れる。MVPでは、まずMap → Camera → Save → Memoriesのコアフローを最優先する。

## 13. Product Priorities

開発優先順位は以下である。

```text
1. Mapでスポットを選ぶ
2. CameraへspotIdを渡す
3. 撮影する
4. 写真をspotId / prefectureIdと紐づけて保存する
5. Memoriesに反映する
6. Homeに7日限定投稿として表示する
7. いいね・コメントを追加する
8. UIを磨く
```

UIの美しさは重要だが、コアフローがつながっていなければアプリとして成立しない。まずは「場所で撮って、場所ごとの思い出に残る」体験を完成させる。

## 14. Success Criteria

MVP段階の成功基準は以下である。

### Product

* ユーザーがMapでスポットを選べる
* Cameraで撮影できる
* 撮影した写真がMemoriesに保存される
* Homeに投稿として表示される
* 7日後にHomeから消える
* Memoriesには残る

### UX

* Home, Map, Camera, Memoriesの役割が明確である
* BeRealやInstagramのコピーに見えない
* 旅行アプリとしての独自性が伝わる
* 初見ユーザーが何をするアプリか理解できる

### Portfolio

* 企画意図を説明できる
* UI設計理由を説明できる
* 外部設計・内部設計を説明できる
* コアフローとデータ設計を説明できる
* 公開までのロードマップを説明できる

## 15. Current Development Focus

現在の開発焦点は以下である。

```text
Map → Camera → Save → Memories
```

このコアフローがピクトリの背骨である。

HomeやMemoriesのUI改善も進めるが、今後は必ず「コアフロー完成に近づいているか」を基準にして実装判断を行う。
